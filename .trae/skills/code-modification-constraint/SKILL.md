# Code Modification Constraint

此 Skill 旨在确保所有的代码修改都符合预定的规范和要求，以保证代码质量、可维护性和一致性。

## 适用场景
- 当用户明确要求修改现有代码时。
- 当进行代码重构或优化时。
- 当添加新功能涉及到修改现有逻辑时。

## 约束规则

### 1. 保持现有风格
- 修改代码时，必须遵循当前文件或项目的代码风格（缩进、命名约定、注释风格等）。
- 不要随意更改与本次修改无关的代码格式。

### 2. 最小化修改范围
- 只修改与需求直接相关的代码，避免“牵一发而动全身”的大规模改动，除非确有必要且经过确认。
- 尽量保持函数的单一职责，不要在修复 Bug 时顺便添加不相关的功能。
- 不要删除任何已有注释。如果要删除某段代码，优先进行注释而不是直接删除，以保留代码的历史记录和上下文。

### 3. 安全性与健壮性
- 修改后的代码必须考虑边界情况和异常处理。
- 确保没有引入新的安全漏洞（如 SQL 注入、XSS 等）。
- 关键逻辑必须包含必要的空值检查和类型断言。

### 4. 可读性与注释
- 复杂的逻辑修改必须添加清晰的注释，解释“为什么”要这样改，而不仅仅是“改了什么”。
- 如果修改了函数的行为，必须同步更新函数的文档注释。

## 使用示例

当用户提出：“帮我优化这个函数的性能”时，调用此 Skill 并执行以下步骤：
1. 分析当前函数的逻辑和性能瓶颈。
2. 提出优化方案，并确保方案符合上述约束规则（如不破坏现有功能、保持代码风格）。
3. 实施修改，并添加必要的注释说明优化点。
